# マソ君の日常

## 概要

筋トレの記録を続けながら、2Dキャラクター「マソ君」を育てるWebアプリです。種目ごとの換算方式で、重量・回数・セット数（自重を使う種目はその日の体重も使います）からトレーニング量を計算し、育成ポイントを獲得できます。ポイントをエサに交換してマソ君にあげると、成長します。ウォーキング・ランニングなどの有酸素は未換算で、時間だけを記録します（ポイントは付きません）。

主な機能は、トレーニングの登録・編集・削除、今日の体重の記録、カレンダーでの記録確認、履歴の分析、5種類のエサの交換・給餌、BGM（トレーニング向け・リラックス向け）の再生です。マソ君の名前とアカウントの表示名は、見えない文字の除去と禁止ワードの判定つきで変更できます。初回画面からメールアドレスで登録し、Supabaseにアカウント別のデータを保存します。次回は有効なセッションが残っていれば自動で入室できます。登録せずに使う場合は「ゲストで入室」を選び、このブラウザに保存します。

Next.js 16、React 19、TypeScript、Tailwind CSS 4、Supabaseを使用しています。

## インストール

1. Node.js 20.9以上を用意し、このフォルダーで依存パッケージをインストールします。

   ```powershell
   npm ci
   ```

2. ゲスト利用だけの場合、追加設定は不要です。アカウント登録とクラウド保存を使う場合は、設定例をコピーしてSupabaseの公開用接続情報を入力します。既存の `.env.local` がある場合は上書きせず、設定内容を確認してください。

   ```powershell
   Copy-Item .env.example .env.local
   ```

   ```dotenv
   NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
   NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
   NEXT_PUBLIC_APP_VERSION=0.1.0
   ```

   `.env.local` はGitに追加しないでください。`NEXT_PUBLIC_` で始まる値はブラウザへ公開されるため、サービスロールキーなどの秘密情報は設定しません。

### Supabaseを使う場合の初期設定

SupabaseのAuthenticationでメールとパスワードによる登録を有効にします。公開環境の **Site URL** は `https://masodiary.vercel.app`、**Redirect URLs** に `https://masodiary.vercel.app/auth/callback` と開発用の `http://localhost:3000/auth/callback` を登録します。確認リンクには `next` パラメータが付くため、`https://masodiary.vercel.app/auth/callback\?next=**` と開発用の同じパターンも追加します。`\?` はURL内の疑問符そのものを指定する記法です（[SupabaseのRedirect URLs](https://supabase.com/docs/guides/auth/redirect-urls)）。メール確認は有効に保ち、登録後に届くリンクを同じブラウザで開いて登録を完了します。公開アプリの環境変数にも同じプロジェクトのURL・公開キーを設定し、環境変数の更新後は再ビルドしてください。

セッションは `@supabase/ssr` のCookieに保存し、Proxyで署名を検証・更新します。パスワードを端末に保存して自動入力する方式ではありません。ログアウトやブラウザデータの削除、Supabase側のセッション失効時は再ログインが必要です。ゲストCookieは端末内データを選ぶための設定だけで、Supabaseへのアクセス権は与えません。

データベースには `supabase/migrations/` のSQLを**番号順に**適用します。アプリを更新・公開する前に適用してください。先にアプリだけを公開すると、記録やエサの保存が失敗します。

| 番号 | 内容 |
| --- | --- |
| `0001` | 初期スキーマ（プロフィール、設定、種目、記録、マソ君、エサ、報酬台帳）とRLS、記録保存・エサやりのDB関数 |
| `0002` | エサの交換・給餌のDB関数 |
| `0003` | 総負荷の換算（4パターン、種目マスター61種）、今日の体重、種目追加のDB関数 |
| `0004` | 名前の正規化（見えない文字の除去）。既存の名前も補正 |
| `0005` | 名前の禁止ワード判定。該当する既存の名前は既定の名前に戻る |
| `0006` | 記録の編集・削除と報酬の差分調整 |
| `0007` | エサを5種類に拡張 |
| `0008` | 有酸素を未換算（時間のみ）として記録 |
| `0009` | クラウド履歴・種目のページ取得に対応する複合インデックス |
| `0010` | 種目・体重・表示名の保存で操作開始時のアカウントを照合 |

Supabase CLIを使う場合の例です。

```powershell
npx supabase init
npx supabase login
npx supabase link --project-ref YOUR_PROJECT_REF
npx supabase db push
```

既に `supabase/config.toml` がある場合、`npx supabase init` は不要です。CLIを使わない場合はSupabaseのSQL Editorで10個のSQLファイルを番号順に実行できます。既存のDBでは適用済みの定義を確認し、未適用の番号だけを実行してください。SQL Editorで手動適用したDBは、CLIのmigration履歴との照合も必要です。適用済みのファイルは編集せず、変更は新しい番号のファイルとして追加します。初期データは登録時のデータベース処理が作成するため、`supabase/seed.sql` は空です。公開環境で一般ユーザーを登録させる場合は、[Supabase標準の送信先制限](https://supabase.com/docs/guides/auth/auth-smtp)を踏まえ、AuthenticationのSMTP設定も行ってください。

## 使い方

1. 開発サーバーを起動し、ブラウザで [http://localhost:3000](http://localhost:3000) を開きます。

   ```powershell
   npm run dev
   ```

2. **記録**画面で日付を選び、部位・種目を選んで、重量・回数・セット数を入力します。自重を使う種目（プッシュアップ、懸垂、スクワットなど）は、種目選択画面の「今日の体重」を使って負荷を計算します。未入力なら直近の体重を使います。保存した記録は、記録画面の「編集」「削除」から直せます。**ホーム**で育成ポイントを確認し、「エサやり」からエサに交換してマソ君にあげます。**履歴分析**では直近7日、部位別、種目別のトレーニング量を確認できます。Supabaseを設定した場合、初回は案内画面からアカウントを登録し、以後はログインして使います。

3. 計算例として、60 kgを10回、3セット記録した場合は次のようになります。

   ```ts
   const volumeKg = 60 * 10 * 3; // 1,800 kg
   const growthPoints = Math.floor(volumeKg / 100); // 18ポイント
   ```

   自重を使う種目は、種目ごとの体重係数を使います。体重70 kgでプッシュアップ（係数0.64）を20回、3セット行った場合は次のとおりです。

   ```ts
   const loadPerRepKg = 70 * 0.64; // 1回あたり44.8 kg
   const volumeKg = loadPerRepKg * 20 * 3; // 2,688 kg
   const growthPoints = Math.floor(volumeKg / 100); // 26ポイント
   ```

   プランクなど秒数で行う種目は、10秒を1回として換算します。ウォーキング・ランニングなどの有酸素は未換算のため、時間（分）だけを記録し、ボリュームは0でポイントは付きません。換算の詳細は [換算ロジック仕様](.docx/換算ロジック仕様.md) を参照してください。

   エサは育成ポイントと交換します。バナナ2ポイント、おにぎり5ポイント、ささみ10ポイント、プロテイン15ポイント、ステーキ40ポイントで、与えるほど大きな経験値になります。1回の交換・給餌は1〜1,000個です。

4. 入力には、重量500 kg、回数200回（秒数の種目は600秒、有酸素は600分）、セット数30、体重20〜300 kg、1回の記録のボリューム50,000 kgまでの上限があります。重量0 kgの記録はできません（自重を使う種目の追加重量は0 kgにできます）。入力欄でEnterキーを押しても保存されません。「この記録を保存」ボタンで確定します。

### 画面と保存先

| 画面 | パス | できること |
| --- | --- | --- |
| ホーム | `/` | マソ君の状態確認、エサの交換・給餌、名前変更 |
| 記録 | `/records` | カレンダーと日別記録の確認 |
| 入力 | `/records/new?date=YYYY-MM-DD` | トレーニングの登録 |
| 編集 | `/records/{記録ID}/edit` | 保存済みの記録の編集（種目は変更できません） |
| 履歴分析 | `/analytics` | トレーニング量の集計 |
| 登録・ログイン | `/welcome`、`/register`、`/login` | アカウントの作成とログイン |

Supabaseに接続してログインした場合、記録・種目・設定・マソ君の状態はアカウントごとに保存されます。初回画面には登録・ログイン・ゲスト入室があり、有効なアカウントのセッションがある場合は自動でアプリを開きます。ゲスト利用では現在のブラウザの `localStorage` に保存され、別のブラウザや端末には引き継がれません。ブラウザのデータを消すと記録も消えます。ゲストのデータはログイン時に自動でクラウドへ移行しません。ホームの設定からログアウト・ゲスト退室ができ、退室だけでは保存した記録は消えません。

### 性能テストに基づく改修

- ゲストの保存はWeb Locksで最新データの読込み・変更・永続化を直列化し、2タブの同時操作で上書きしないようにします。保存に失敗した場合は成功表示を出しません。Web Locks非対応ブラウザでは既存記録の閲覧はできますが、保存には対応ブラウザが必要です。
- キャラクター画像は透過WebPを使用します。原SVGを保持し、`node scripts/optimize-maso-images.mjs` で再生成できます。
- 履歴分析は読込み中と表示後の配置をそろえ、同日の大量記録は25件ずつ表示します。編集後は元のページに戻れます。
- クラウドの記録保存・編集・削除後は、変更した記録とDB上の育成ポイントだけを読み込みます。体重が変更された場合だけ、その日の体重も確認します。保存ごとの履歴全件再取得を避けます。
- 性能テストの生データ・報告書・ブラウザ確認用ファイルは `output/playwright/` に保存し、Gitには含めません。

記録を編集・削除すると、育成ポイントは付与済みの合計を基準に調整されます。すでにエサへ交換して使ったポイントは、0を下回るまで戻しません。

BGMは画面上部や設定から曲・音量・再生状態を変更できます。トレーニング向け4曲（初期設定）とリラックス5曲があります。トレーニング向けはブラウザ内で生成するため、音源ファイルはありません。ブラウザの自動再生制限により、最初のクリックやタップ後に再生される場合があります。BGMの設定はブラウザごとに保存され、アカウント間では同期しません。

## 運用

1. 変更を提案する場合は、このリポジトリをフォークして作業ブランチを作成します。
2. 変更後に次のコマンドで確認します。

   ```powershell
   npm run lint
   npm run typecheck
   npm test
   npm run build
   ```

3. DBの関数や制約を変えた場合は、実DB検証も実行します（手順は [検証資料](supabase/tests/README.md)）。メモリ内のPostgreSQL（PGlite）で、マイグレーションを番号順に適用して確認します。外部のDBには接続しません。

4. 変更内容と確認結果を記載してプルリクエストを送信します。本番向けの動作確認では、Supabaseの認証URL、メール設定、migrationの適用状態も確認してください。

設計と開発の詳細は [要件定義書](.docx/要件定義書.md)、[基本設計書](.docx/基本設計書.md)、[開発手引き](.docx/開発手引き.md) を参照してください。総負荷の計算は [換算ロジック仕様](.docx/換算ロジック仕様.md)、失敗時の案内は [エラー処理方針](.docx/エラー処理方針.md) にまとめています。[実装状況](.docx/実装状況.md) は記載日時の時点の記録です。アカウントごとのデータ分離テストの手順と検証範囲は [検証資料](supabase/tests/README.md) にあります。
