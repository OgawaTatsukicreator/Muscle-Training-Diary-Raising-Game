# エラー処理の方針

更新日：2026年10月5日

保存・編集・交換などの操作が失敗したとき、利用者が**次に何をすればよいか分かる**ことを目的にした方針です。以前はほとんどの失敗を「もう一度お試しください」にまとめていたため、入力の不備・通信断・ログイン切れを区別できませんでした。

## 1. 分類（`lib/errors/rpc-error.ts`）

Supabaseの呼び出しで返るエラーを、次の種類に分けて文言を決めます。DB関数が返すエラーコードと対応しています。

| 種類 | 主な条件 | 利用者への案内 | 再試行 |
|---|---|---|---|
| network | 通信失敗・タイムアウト・fetch例外 | 通信できません。接続を確認 | 可 |
| auth | `28000`・JWT期限切れ・401 | ログインの有効期限が切れました | 不可（再ログイン） |
| forbidden | `42501`・403（アカウント不一致） | 許可されていません。再読み込み | 不可 |
| validation | `22023`・`23514`・400 | 入力内容を確認 | 不可 |
| name-not-allowed | メッセージ `name not allowed` | この名前は使用できません（禁止語は示さない） | 不可 |
| not-found | `P0002`・404 | 見つかりません。再読み込み | 不可 |
| conflict | `23505`・`40001`・`40P01` | ほかの操作と重なりました | 可 |
| rate-limit | 429 | 操作が集中しています | 可 |
| unavailable | `PGRST202`（関数が未配備） | サーバー側の更新が未反映。管理者へ | 不可 |
| server | 5xx | サーバーで問題が発生 | 可 |

- 通信が切れて fetch が例外を投げても、`settle()` が値として返すので、画面が「保存中」のまま固まりません。
- 画面の検証をすり抜けたサーバー側の拒否は、汎用の失敗にせず、直す場所が分かる形にします（`workout-error.ts`）。
  - 体重が必要な種目で体重がない → 体重欄を指摘
  - 1記録のボリュームが過大 → ボリュームを指摘
  - 記録が見つからない（別端末で削除済み）→ 再読み込みを案内
- アイテムの「足りない」は、別端末・別タブで先に使われたときに起きます。画面の数字が古いので、最新の状態を取り直して表示します（`food-error.ts`）。

## 2. 機能ごとの扱い

| 機能 | 起こり得る問題 | 対応 |
|---|---|---|
| 名前の変更 | 見えない文字だけの名前で表示が空白になる | 保存前に見えない文字を除去し、見える文字がなければ拒否。DBも同じ規則で拒否・補正 |
| | 保存済みの名前が不正（過去データ） | 読み込み時は既定の名前で代替。読み込み全体を失敗させない |
| | 保存は成功したが応答を読めない | 最新の状態を取り直して反映 |
| | 他の操作の直後に名前を保存し、育成値を古い値で上書き | 名前だけを差し替える |
| 禁止ワード | 表記ゆれ（全角・カタカナ・記号の挿入・数字置換） | 判定前に正規化。英単語は単語単位で判定し誤検出を減らす |
| | 新規登録の表示名が禁止語 | 登録は失敗させず既定名にして、画面で事前に案内 |
| | APIを直接呼ぶ回避 | DB側の関数で拒否（クライアントだけに頼らない） |
| BGM | 自動再生の制限 | `blocked` 状態にして、画面の操作後に再生 |
| | 生成の失敗・非対応ブラウザ | `error` 状態にして再試行ボタンを表示 |
| | 曲の切替が重なる | 古い再生要求の結果は無視（要求番号で判定） |
| 記録の編集・削除 | 二重送信・再送 | 要求IDで冪等。削除は記録ごとに同じIDを再利用 |
| | 別端末で先に削除された | 編集は「見つかりません」、削除は成功扱い |
| | ポイントを使った後に減らす | 0未満まで戻さない。付与済みの合計を基準にするので水増しも不可 |
| | 有酸素の記録に重量・セット数が送られた | サーバーは重量とアシストを無視し、未換算（ボリューム0）で保存する。時間は1〜600分 |
| エサ | 新しい種類の保存先がない旧サーバー | RPC結果の `items` が無くても0で補う。関数未配備は管理者への案内 |

## 3. 検証

- 単体テスト: 分類と文言（`lib/errors/*.test.ts`）、各ドメイン関数、BGMの状態遷移
- 実DB検証（PGlite）: 各RPCの拒否・冪等・権限・アカウント分離。`supabase/tests/README.md`
- 画面操作: 見えない名前の拒否、編集・削除、エサの交換と給餌、BGMの切替をブラウザで確認

## 4. 確認できていないこと

- 実際のSupabase・ネットワーク断・ログイン期限切れの挙動（分類は単体テストで確認。実環境の確認は未実施）
- BGMの音の聞こえ方（レンダリングしたデータでピーク・クリップ・周波数バランスは確認したが、耳での確認は未実施）
