# 総負荷（ボリューム）の換算ロジック仕様

更新日：2026年10月5日

マソ君の成長ポイントの元になるボリュームを、種目ごとの換算パターンで計算するための仕様です。計算結果は育成のための**目安**であり、厳密な生体力学値ではありません。係数はバイオメカニクスの文献（Ebben 2011、ExRx.net等）を参考にした代表値で、固定です。

## 1. 計算式

```text
総ボリューム = 1回あたりの総負荷 × 回数 × セット数
成長ポイント = floor(総ボリューム / 100)
```

1回あたりの総負荷は、種目に設定された4つのパターンのどれかで決まります。BW は「その日の体重（kg）」、ratio は種目の体重係数です。

| パターン | 対象 | 総負荷 | 例 |
|---|---|---|---|
| A 純・外部ウエイト | 体が固定され、自重が上下しない種目 | `重量` | ベンチプレス、ラットプルダウン |
| B 自体重＋ウエイト | 体も一緒に持ち上げる下半身種目 | `重量 + BW × ratio` | スクワット（0.88）、ランジ（0.74） |
| C 純・自体重 | 床や台に体を支持して自重の一部を負荷にする種目 | `BW × ratio + 重量` | プッシュアップ（0.64）、クランチ（0.40） |
| D ぶら下がり・支持 | 自重のほぼ全てを持ち上げる種目 | `BW × ratio + 重量 − アシスト` | 懸垂（0.90）、ディップス（0.91） |

- C、D の「重量」は加重（ベルト等）で、なければ0です。D の「アシスト」はマシンの補助重量で、D 以外では無視します。
- 総負荷が0以下になる入力（アシストが大きすぎる等）は保存できません。
- lb で入力した重量とアシストは、`1 lb = 0.45359237 kg` で kg に換算して保存します。

### 静的種目（プランクなど）

秒数で入力します。**10秒 = 1レップ**として換算します。内部では「1秒あたり負荷 = 総負荷 / 10」を保存し、回数欄に入れた秒数をそのまま掛けます。

例：体重70kg、プランク（C、0.65）を60秒×2セット → `70 × 0.65 / 10 × 60 × 2 = 546 kg`

### 有酸素（未換算）

ウォーキング、ランニングなど**部位が「有酸素」の種目は、ボリュームへ換算しません**（2026年10月5日に決定）。距離・時間・強度を kg に直す共通の根拠がなく、換算するとウエイトの記録と釣り合わないためです。

- 記録するのは**時間（分）だけ**です。入力欄は「時間」1つで、重量・セット数・アシストは使いません。`回数` の列に分を保存し、上限は600分（10時間）です。
- ボリューム、1回あたりの総負荷、重量は0で保存します。育成ポイントは付きません（`floor(0 / 100) = 0`）。
- 履歴分析のボリューム、部位別・種目別の集計、記録画面のセット数・回数の合計には含めません。記録一覧には「30分 · 未換算」、記録画面には有酸素の合計時間を表示します。
- 編集と削除はほかの記録と同じです。報酬の調整額は0です。
- 判定は種目の換算パターンではなく**部位**で行います。ユーザーが有酸素に追加した種目も同じ扱いです。DBの `save_workout` / `compute_workout_values` と、TypeScriptの `UNCONVERTED_BODY_PARTS` が同じ規則を持ち、単体テストが一致を確認します。
- サーバーは、重量・アシスト・セット数が送られても重量とアシストを無視して未換算で保存します（画面は常に重量0・セット数1を送ります）。

## 2. 種目マスター

標準の61種目（貼り付けの58種目＋既存の3種目）を持ちます。正本は次の2つで、単体テストが一致を確認します。

- TypeScript：`lib/data/exercise-master.ts`
- SQL：`supabase/migrations/0003_load_calculation.sql` の `exercise_master()`

| パターン | 種目数 |
|---|---|
| A | 23（＋トライセプスエクステンション、ウォーキング、ランニング） |
| B | 11 |
| C | 18 |
| D | 6 |

複数の部位にまたがる種目は主働部位に分類しています。ウォーキング、ランニングなどの有酸素は、マスター上はパターンAですが、部位が有酸素のため換算パターンは使いません（前述の「有酸素（未換算）」）。

既存の標準種目のIDは変更しません（例：スクワットはバーベルスクワットへ改名しますが、IDは `default-squat` のままです）。

## 3. ユーザーが追加した種目

換算パターンは**部位から自動判定**し、ユーザーが選ぶ質問は次の2つだけです。サーバー側の `add_exercise` が決め、クライアントから直接パターンを指定することはできません。

| 部位 | 追加時の扱い | パターン / 係数 |
|---|---|---|
| 胸・背中・肩・腕・その他 | 質問なし（ウエイトのみ） | A / 0 |
| 有酸素 | 質問なし（未換算。時間だけを記録） | 換算しない（保存上はA / 0） |
| 脚 | 「自重も使う種目ですか？」と質問 | はい→B / 0.74、いいえ→A |
| 腹 | 自重のみ。「秒数で行う種目」のチェックあり | C / 0.50（秒数ならプランクと同じ静的種目） |

背中の自重種目（懸垂など）はマスターに含めているため、追加種目では質問しません。

## 4. 体重の扱い

- 1日1件を `body_weight_logs` に保存します。同じ日の再入力は上書きです。範囲は20〜300kgです。
- 入力画面の「今日の体重」カード（種目選択画面の上部）で入力し、「記録」で保存するか、記録の保存時に一緒に送ります。
- 入力がなければ、**記録日以前で最も新しい体重**を使います。パターンB・C・Dで体重が一度も記録されていなければ保存できません。
- パターンAのみの日は、体重は不要です（入力すれば記録だけされます）。
- 記録には、計算に使った体重・アシスト・1回あたりの総負荷を保存します。後から係数を調整しても、過去の記録のボリュームは変わりません。

## 5. 入力の上限

クライアントの入力欄とサーバー（`save_workout`）で同じ値を検証します。

| 項目 | 上限 |
|---|---|
| 重量・アシスト | 500kg（lbは換算後） |
| パターンAの重量 | 0より大きい値（B・C・Dの追加重量は0可） |
| 回数 | 200回（静的種目は600秒、有酸素は600分） |
| セット数 | 30 |
| 体重 | 20〜300kg |
| 1回の記録のボリューム | 50,000kg |

## 6. 既存データの扱い

マイグレーション 0003 より前の記録は再計算しません（当時の体重が分からないため）。`load_per_unit_kg` に保存済みの重量を入れ、ボリュームは従来どおり `重量 × 回数 × セット数` のままです。

有酸素を未換算にした（0008）より前に、重量つきで保存された有酸素の記録も書き換えません。保存済みのボリュームと育成ポイントはそのままです。そのような記録を編集して保存すると未換算の記録になり、付与済みのポイントは調整で戻ります（使用済みの分は0未満まで戻しません）。重量0で保存された有酸素の旧記録は、回数の値を分として表示します。

## 7. 未解決事項

- 有酸素の距離・強度の記録と、将来の換算（現在は未換算で、時間だけを記録。距離はメモに書く）
- レッグプレスなどマシンの角度補正（現在は係数のみ）
- 同じ自重でも種目で強度が違う点（係数は固定の目安で、ユーザー編集は用意しない）
- 自重種目は体重が重いほどボリュームが大きくなる。バランスは運用しながら確認する
