# 「マソ君の日常」実装状況

更新日：2026年10月5日（公開後の指摘への対応を追記。それ以前の記述は2026年7月時点のものを含みます）

## 現在地

主要4画面を使ったローカルプレビューが動く状態です。ホームから記録を追加すると、カレンダー、日別一覧、履歴分析、育成ポイントとエサへ反映されます。

Supabaseについては、クライアント、メールリンク認証、セッション更新、初期migrationまで作成済みです。まだアプリの記録データをSupabaseへ接続していないため、現時点の保存先はブラウザの `localStorage` です。クラウド保存済みとは扱いません。

開発手引きの区分では、Sprint 0の基盤と、Sprint 2からSprint 5に含まれる画面のローカル版を先に縦に通した段階です。Sprint 1のDBと認証は下地までで、実環境を使った確認が残っています。

## 確定した暫定仕様

| 項目 | 現在の値 |
|---|---|
| デフォルトセット数 | 3セット。画面で1〜10セットへ変更可能 |
| DBの重量単位 | kg |
| lb換算 | `1 lb = 0.45359237 kg` |
| 育成ポイント | `floor(volume_kg / 100)` |
| エサ | 5種類。バナナ 2pt→4XP、おにぎり 5pt→10XP、ささみ 10pt→21XP、プロテイン 15pt→30XP、ステーキ 40pt→90XP（育成ポイントと交換） |
| 次レベルの必要経験値 | `100 × 現在レベル` |
| 日付基準 | `Asia/Tokyo` |
| 週の開始 | 月曜日 |
| 未来日の記録 | 保存不可 |
| 変更できる名前 | マソ君の名前、アカウントの表示名（見えない文字の除去・禁止ワードの判定あり） |
| 記録の編集と削除 | 可能。育成ポイントは付与済みの合計を基準に調整（使用済み分は0未満まで戻さない） |

自重種目のボリュームは、種目ごとの4つの換算パターンとその日の体重から計算します。仕様は [換算ロジック仕様.md](換算ロジック仕様.md) にまとめています。有酸素運動（距離・時間）の換算規則は未確定で、現在は重量、回数、セット数を使います。

## 2026年10月の追加（公開後の指摘への対応）

公開後にいただいた指摘への対応です。DBの変更はマイグレーション 0003〜0007 に分けています。適用順は番号順で、**アプリより先にDBへ適用**してください（先にアプリを公開すると保存が失敗します）。

| 指摘 | 対応 | 詳細 |
|---|---|---|
| 重量0でも登録でき、非現実的な値が入る | 重量・回数・セット数・体重・ボリュームに上限、重量0は不可（自重種目の追加重量は0可） | [換算ロジック仕様.md](換算ロジック仕様.md) |
| 自重種目の負荷が正しくない | 4つの換算パターンと当日の体重で総負荷を計算。今日の体重を入力欄に追加 | 同上（0003） |
| Enterで勝手に記録される | 入力欄のEnterでは保存せず、保存ボタンのみで確定 | |
| 記録を編集できない | 記録の編集・削除（確認つき）を追加 | 0006 |
| 名前変更後に表示が空白になる | 見えない文字だけの名前を除去・拒否（クライアントとDB）。既存データも補正 | 0004 |
| 不適切な名前がそのまま表示される | 禁止ワードの判定を、クライアントとDBの両方に追加 | 0005 |
| 餌のバリエーションが少ない | 5種類に増加 | 0007 |
| BGMがゆったりした曲だけ | トレーニング向け4曲を追加し、新規ユーザーの既定にした（Web Audioで生成。音源ファイルは増えていません） | |
| キャラクターが1人だけ | 今回は対応しない | |

エラー処理の方針は [エラー処理方針.md](エラー処理方針.md)、DBの検証結果は `supabase/tests/README.md` にあります。

### 禁止ワードの更新方法

語彙は `lib/domain/name-filter-terms.json` です。変更したら `node scripts/generate-name-filter-sql.mjs` でSQLを作り、**新しいマイグレーション**として適用してください（適用済みのファイルは編集しません）。TSとSQLの語彙が一致しているかは単体テストで確認します。初期の語彙は最小限なので、運用しながら見直してください。

## 実装済み

### プロジェクト基盤

- Next.js 16、React 19、TypeScript strict、Tailwind CSS 4
- Supabase SSRクライアント、Zod、Lucide、Vitest
- `lint`、`typecheck`、`test`、`build` のnpm scripts
- 日本時間の日付処理、kgとlbの換算、報酬と経験値計算をUIから分離
- 404、読込中、画面エラーの共通表示
- スマートフォン向けボトムナビゲーション

### ホーム

- SVG版のマソ君表示
- レベル、経験値ゲージ、育成ポイント、エサ数の表示
- エサ1個の使用と、余剰経験値を繰り越すレベルアップ計算
- レベル上限999と、上限到達後の経験値制限
- マソ君の名前変更
- 当日のトータルボリュームと記録件数
- ローカルプレビューデータの消去

### トレーニング入力

- 日付と8部位の選択
- 部位ごとのデフォルト種目
- 未登録種目の追加
- 重量、kgまたはlb、回数、セット数、メモの入力
- 入力中のトータルボリューム計算
- Zodによる入力検証
- 未来日禁止、入力上限、メモ500文字制限
- 二重送信を避けるリクエストID
- 空の日付・重量を保存しない入力検証
- 保存時の育成ポイントとエサ付与

### 記録と設定

- 月曜始まり、6週表示の月間カレンダー
- 記録日のマーカー、未来日の選択禁止
- 選択日の記録一覧と合計ボリューム
- デフォルトセット数と重量単位の変更
- アプリバージョンと現在の保存先の表示

### 履歴分析

- 直近7日の日別ボリューム
- 全期間の部位別ボリューム
- 全期間の種目別ボリューム順位
- 記録がないときの案内表示

### Supabaseの下地

- ブラウザ用とサーバー用のクライアント
- Next.js Proxyでのセッション更新と未認証時のログイン誘導
- メールリンク送信、認証callback、ログアウト
- `profiles`、`user_settings`、`exercises`、`workout_logs`、`maso_status`、`foods`、報酬と成長の履歴テーブル
- 全ユーザーデータ表のRLS
- 種目と記録の所有者を一致させる複合外部キー
- 記録保存と報酬付与をまとめる `save_workout` DB関数
- エサ使用とレベル更新をまとめる `feed_maso` DB関数
- リクエストIDを使った再実行対策
- 新規ユーザー用の初期設定、マソ君、デフォルト種目を作るトリガー

## 次の作業

### 1. Supabase実環境

1. Supabaseプロジェクトを作る。
2. `supabase/migrations/0001_initial.sql` を適用する。
3. ローカルと公開先の認証redirect URLを登録する。
4. `.env.local` にURLと公開用キーを設定する。
5. メールリンクで新規ユーザーを作り、初期データが作られることをSQL Editorで確認する。

### 2. アプリデータの接続

1. ホーム、記録、分析で使うSupabaseの取得関数を作る。
2. 記録保存を `save_workout` DB関数へ接続する。
3. エサやりを `feed_maso` DB関数へ接続する。
4. 種目追加、設定変更、名前変更を認証ユーザー単位で保存する。
5. 読込中、通信失敗、再試行の表示を各操作の近くへ出す。
6. `DemoDataProvider` をプレビュー専用に残すか、Supabase用のデータ層へ置き換える。

### 3. ユーザー分離の確認

2人のテストユーザーを作り、記録、種目、設定、マソ君、報酬履歴を互いに読めないことを確認します。ブラウザから他人のIDを送る試験と、SQL経由の試験を行います。

### 4. 残りのMVP

報酬台帳の差分規則を決めてから記録編集と削除を作ります。その後、週別・月別分析、レベル別画像、E2Eテスト、Vercel公開へ進みます。
