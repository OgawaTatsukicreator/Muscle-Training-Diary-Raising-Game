# 「マソ君の日常」実装状況

更新日：2026年10月5日（公開後の指摘への対応を反映。記録は更新日時点のものです）

## 現在地

公開後にいただいた指摘への対応を実装した状態です。主要4画面（ホーム、記録、入力、履歴分析）、アカウント登録・ログイン、ユーザーごとのクラウド保存、記録の編集・削除、5種類のエサ、トレーニング向けBGMが動きます。

保存先は2通りです。Supabaseの接続情報があれば、メールアドレスとパスワードで登録・ログインし、データをアカウントごとにクラウドへ保存します。接続情報がなければ、ブラウザの `localStorage` に保存するローカルプレビューとして動きます。

データベースの変更は `supabase/migrations/0001`〜`0008` です。**アプリより先にDBへ番号順に適用してください**（先にアプリを公開すると保存が失敗します）。0003〜0008は公開後の指摘への対応です。実環境への適用状況は、このリポジトリからは確認できません。

## 確定した仕様

| 項目 | 現在の値 |
|---|---|
| デフォルトセット数 | 3セット。画面で1〜10セットへ変更可能 |
| DBの重量単位 | kg |
| lb換算 | `1 lb = 0.45359237 kg` |
| ボリューム | 種目ごとの4つの換算パターンとその日の体重から計算（[換算ロジック仕様.md](換算ロジック仕様.md)）。静的種目は10秒＝1レップ |
| 有酸素 | **未換算**。時間（分）だけを記録し、ボリュームは0、育成ポイントは付かない |
| 入力の上限 | 重量500kg、回数200回（静的種目600秒、有酸素600分）、セット数30、体重20〜300kg、1回の記録のボリューム50,000kg |
| 育成ポイント | `floor(volume_kg / 100)` |
| エサ | 5種類。バナナ 2pt→4XP、おにぎり 5pt→10XP、ささみ 10pt→21XP、プロテイン 15pt→30XP、ステーキ 40pt→90XP（育成ポイントと交換） |
| 次レベルの必要経験値 | `100 × 現在レベル`（上限レベル999） |
| 日付基準 | `Asia/Tokyo` |
| 週の開始 | 月曜日 |
| 未来日の記録 | 保存不可 |
| 変更できる名前 | マソ君の名前、アカウントの表示名（見えない文字の除去・禁止ワードの判定あり） |
| 記録の編集と削除 | 可能。育成ポイントは付与済みの合計を基準に調整（使用済み分は0未満まで戻さない） |

## 2026年10月の追加（公開後の指摘への対応）

| 指摘 | 対応 | 詳細 |
|---|---|---|
| 重量0でも登録でき、非現実的な値が入る | 重量・回数・セット数・体重・ボリュームに上限、重量0は不可（自重種目の追加重量は0可） | [換算ロジック仕様.md](換算ロジック仕様.md) |
| 自重種目の負荷が正しくない | 4つの換算パターンと当日の体重で総負荷を計算。今日の体重を入力欄に追加 | 同上（0003） |
| ウォーキング・ランニングを記録できない（重量0が不可のため） | 有酸素は未換算とし、時間（分）だけを記録できるようにした | 同上（0008） |
| Enterで勝手に記録される | 入力欄のEnterでは保存せず、保存ボタンのみで確定 | |
| 記録を編集できない | 記録の編集・削除（確認つき）を追加 | 0006 |
| 名前変更後に表示が空白になる | 見えない文字だけの名前を除去・拒否（クライアントとDB）。既存データも補正 | 0004 |
| 不適切な名前がそのまま表示される | 禁止ワードの判定を、クライアントとDBの両方に追加 | 0005 |
| 餌のバリエーションが少ない | 5種類に増加 | 0007 |
| BGMがゆったりした曲だけ | トレーニング向け4曲を追加し、新規ユーザーの既定にした（Web Audioで生成。音源ファイルは増えていません） | |
| キャラクターが1人だけ | 今回は対応しない | |

エラー処理の方針は [エラー処理方針.md](エラー処理方針.md)、DBの検証結果は `supabase/tests/README.md` にあります。

### 禁止ワードの更新方法

語彙は `lib/domain/name-filter-terms.json` です。変更したら `node scripts/generate-name-filter-sql.mjs` でSQLを作り、**新しいマイグレーション**として適用してください（適用済みのファイルは編集しません）。TSとSQLの語彙が一致しているかは単体テストで確認します。初期の語彙は最小限なので、運用しながら見直してください。

### マイグレーションの適用時に起きること

- 0004：表示名・マソ君の名前・種目名から見えない文字を取り除きます。見える文字が残らない名前は、既定の名前（「トレーニー」「マソ君」）になります。
- 0005：禁止ワードに当たる既存の名前は、既定の名前に戻ります。利用者への通知はありません。
- 0003：既存の記録は再計算しません。標準種目が全ユーザーに補完され、「スクワット」は「バーベルスクワット」に改名されます（IDは変わりません）。
- 0008：既存の有酸素の記録は書き換えません。

## 実装済み

### プロジェクト基盤

- Next.js 16、React 19、TypeScript strict、Tailwind CSS 4
- Supabase SSRクライアント、Zod、Lucide、Vitest
- `lint`、`typecheck`、`test`、`build` のnpm scripts
- 日本時間の日付処理、kgとlbの換算、報酬・経験値・ボリューム計算をUIから分離
- 404、読込中、画面エラーの共通表示
- スマートフォン向けボトムナビゲーション

### アカウントとクラウド保存

- メールアドレスとパスワードによる登録・ログイン・ログアウト、メール確認後のcallback、セッション更新、未認証時のログイン誘導
- 初回登録時の初期データ作成（設定、マソ君、エサ、標準種目61種）
- 全ユーザーデータ表のRLSと、記録・報酬・エサの更新をDB関数（RPC）経由に限定する権限
- 保存・編集・削除・交換・エサやり・名前変更・種目追加・体重保存のRPC。リクエストIDによる再実行対策、ロック順の統一
- クラウド用とローカル用のデータ層（`AppDataProvider`、`DemoDataProvider`）。両方で同じ操作と検証
- 通信断・ログイン切れ・入力不備などを分類して案内するエラー処理（[エラー処理方針.md](エラー処理方針.md)）

### ホーム

- SVG版のマソ君表示、レベル、経験値ゲージ、育成ポイント、エサ5種の所持数
- 育成ポイントとエサの交換、エサやり（1回1〜1,000個）、余剰経験値を繰り越すレベルアップ計算、レベル上限999
- マソ君の名前変更（見えない文字の除去・禁止ワードの判定）
- 当日のトータルボリュームと記録件数
- ローカルプレビューデータの消去

### トレーニング入力

- 日付と8部位の選択、部位ごとの標準種目（61種）、未登録種目の追加（部位から換算パターンを自動判定。脚は自重の有無、腹は秒数かを質問）
- 今日の体重の入力（種目選択画面の上部。未入力なら直近の体重を使う）
- 種目の換算パターンに応じた入力（追加重量、アシスト、静的種目の秒数、有酸素の時間）と、入力中のトータルボリューム計算
- Zodによる入力検証、上限、未来日禁止、メモ500文字制限、Enterでの意図しない保存の防止
- 二重送信を避けるリクエストID
- 保存時の育成ポイント付与

### 記録と設定

- 月曜始まり、6週表示の月間カレンダー、記録日のマーカー、未来日の選択禁止
- 選択日の記録一覧と合計（種目数・セット数・回数・ボリューム、有酸素の合計時間）
- 記録の編集（種目は変更不可）と削除（確認つき、論理削除）。報酬は台帳で差分調整
- デフォルトセット数と重量単位の変更
- アプリバージョンと現在の保存先の表示

### 履歴分析

- 直近7日の日別ボリューム、全期間の部位別・種目別ボリューム
- 有酸素（未換算）はボリューム集計に含めず、件数と合計時間を注記
- 記録がないときの案内表示

### BGM

- トレーニング向け4曲（Web Audioでブラウザ内に生成）とリラックス5曲（CC0の音源ファイル）
- 曲・音量・再生状態の切り替え。設定はブラウザごとに保存
